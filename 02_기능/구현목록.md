# 02 기능 — 무엇을 구현했는가

## 피그마와 기획안에서 확인한 백엔드 요구사항

- 온보딩의 위치 선택: 현재 캠퍼스가 하나이므로 프런트 정적 선택으로 충분하며, 다기관 확장 시 캠퍼스 API가 필요합니다.
- 캠퍼스 지도: 건물명, 코드, 좌표, 우선순위, 최대 밀도를 서버에서 제공합니다.
- 메인 시뮬레이터: 건물별 10~22시 밀도와 역산 풍속, 설치 검토 문구를 제공합니다.
- 계산 조건: 면적, 효율, 거리, 각도, 운전시간, 운전일, 요금, 탄소계수, 설치비를 검증합니다.
- 수익 상세: 연 발전량, 절감액, 단순 투자 회수기간과 적용 조건을 반환합니다.
- 환경 상세: 연 탄소 저감량과 적용 계수를 반환합니다.
- 기준안 비교: 기준/현재 요청을 각각 재계산해 전력 절대 차이와 변화율을 반환합니다.
- 현장 확장: 센서·배기구·측정시각·시간대·품질·HVAC 운전상태를 저장하고 조회합니다.
- 신뢰성: 누락을 0으로 바꾸지 않으며 400/404 오류와 필드별 검증 결과를 제공합니다.

## 의도적으로 제외한 범위

- 로그인/회원: 피그마에서 선택 기능이고 현재 학술제 공개 데모 흐름에는 계정별 저장 요구가 없습니다.
- 3D 모델·바람 애니메이션: 렌더링 책임이므로 프런트에 유지합니다.
- CFD/검증된 실제 터빈 성능곡선: 현재 곡선은 기능 검증용 DRAFT이며 설치 판단에 사용할 수 없습니다.
- 설치 추천 확정: 현장 안전·설비 영향 검증 전에는 검토 우선순위로만 표시합니다.
