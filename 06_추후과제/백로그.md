# 06 추후 과제

## 현장 데이터 확보 전 필수 결정

- 정확한 건물 ID·명칭·지도 좌표와 배기구 ID/치수/위치
- 센서 모델, 교정 주기, 측정 간격, 결측/이상치 처리 규칙
- HVAC 운전상태 수집 방식과 압력손실·소음 허용 기준
- 터빈별 성능곡선, 컷인 풍속, 정격·최대 풍속
- 실제 전기요금과 탄소 배출계수의 출처·적용 기간
- 설치비/유지관리비/성능 저하/할인율을 포함할지 여부

## 백엔드 다음 단계

1. PostgreSQL 운영 프로필과 비밀값 관리
2. 실제 센서 프로토콜 연동과 재시도 큐(현재 배치 API는 최대 1,000건·clientRecordId 중복 방지)
3. 자동 품질 판정 규칙과 정기 집계 작업(현재는 품질 플래그 수동 변경·이력 보존)
4. 검증된 터빈 성능곡선과 운전일정의 승인·버전 관리
5. 후보 판정 외 전체 관리자 수정 이력과 감사 로그
6. 계정별 시나리오 저장이 확정될 경우 인증·인가
7. 모니터링, 배포 파이프라인, 백업·복구

## 현재 구현됐지만 실제 자료로 교체해야 하는 항목

- 배기구 좌표·면적: `ESTIMATED`
- 센서 제조사·모델·교정정보: `UNVERIFIED` / `UNKNOWN`
- 터빈 성능곡선과 요금·탄소계수: `DRAFT`
- 배치 최적화: 거리·각도 설명용 `HEURISTIC-v1`

로그인은 피그마상 선택 기능이므로 현재 공개 데모에는 제외했습니다. 개인별 저장·관리자 입력 요구가 확정되는 시점에 역할 모델과 함께 추가하는 것이 안전합니다.
